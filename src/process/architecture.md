# Processing architecture

`research_runner.py` reads active source records, uses a mini OpenAI model for strict source-grounded assessment, and saves every result or error under a version and source hash. The first-pass `--skip-failed` option processes only unseen records so saved failures can be handled by a later provider pipeline. Four-record batches reduce output truncation. `research_store.py` keeps classifications separate from original feedback.

`research_dashboard.py` exposes known mechanisms separately from reported failures with unclear causes and retrieval needs or successes without a failure. It also groups failed records by provider limits, evidence validation, batch output, and other errors. `research_report.py` exports the same reconciled interpretation.

The nonworking GLM 4.7 screening pilot was removed at the user's request. The current Phase 1 catalog assessment uses the project's OpenAI route. No provider scheduler or GLM screening result contributes to the catalog.

`catalog_schema.py` defines multi-tag Phase 1 assessments aligned to the assignment's partial-memory retrieval question. It separates direct memory issues, adjacent reported retrieval issues, requests, successful search, related context, unrelated rows, unclear rows, and generated scenarios. Tags cover remembered clues, explicitly forgotten details, search methods, observed symptoms, and retrieval journey stages. Source quotes are checked against row text, and atomic web summaries remain a distinct evidence type. `catalog_extract.py` sends bounded batches to OpenAI with strict structured output. `catalog_store.py` saves versioned decisions by full-row content hash. `catalog_runner.py` processes all active catalog rows with worker limits, batch splitting, durable per-row results, and resumable runs. Focused tests and a mixed live pilot passed before the full run.

An early full-run quality check found two unsupported direct-memory labels. Version `phase1-catalog-v4` requires an explicit memory-gap phrase in the original target description and downgrades unsupported cases to adjacent retrieval issues. `catalog_migrate.py` reused 235 previously completed decisions and corrected those two labels without repeating paid calls. Exact source spans are retained when the model copies them; if it paraphrases a required issue span, validation stores the full original row text for later semantic sample review instead of inventing a quote. The current run uses 8-row or 6,500-character batches with six paced workers and per-row checkpoints.

`catalog_chat.py` answers research questions from assessed catalog rows. Evidence packing includes remembered clues, forgotten details, search methods, target media, and related quotes. The system prompt locks scope to Google Photos, treats user text and quotes as untrusted data (prompt-injection resistance), asks one clarifying question when the query is vague, and prioritizes the incomplete-memory research themes (kinds of media, what people remember, what they forget, how they search).
